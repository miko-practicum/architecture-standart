# ADR: Передача актуальных депозитных ставок в кол-центр и партнёрский кол-центр

**Автор:** команда цифровой трансформации банка «Стандарт»  
**Дата:** 2026-09-12  
**Статус:** Proposed

## Функциональные требования

| № | Действующие лица или системы | Use Case | Описание |
| :-: | :- | :- | :- |
| 1 | Менеджер депозитного бэк-офиса, АБС | Вести актуальные ставки | Сотрудник депозитного бэк-офиса ведёт базовые депозитные ставки в АБС вместо Excel-файлов. Изменения сохраняются с историей и датой вступления в силу. |
| 2 | Менеджер кредитного бэк-офиса, АБС | Передать данные для специальных ставок | Кредитный бэк-офис обновляет показатели кредитного риска и данные, влияющие на специальные ставки. Доступ между депозитным и кредитным блоком разграничен ролями. |
| 3 | АБС, сервис ставок | Опубликовать ставки | АБС публикует актуальные ставки и признаки продуктов в сервис ставок MVP. Онлайн-каналы и кол-центр читают ставки из этого сервиса, а не из Excel и не напрямую из БД АБС. |
| 4 | Оператор кол-центра банка, система кол-центра | Проконсультировать клиента по ставкам | Оператор видит в системе кол-центра актуальные депозитные ставки и условия продуктов во время звонка. |
| 5 | Сервис ставок, система кол-центра банка | Передать ставки во внутренний кол-центр | Система кол-центра получает ставки через внутренний API или синхронизацию с Rate Cache. |
| 6 | Сервис ставок, SFTP, партнёрский кол-центр | Передать ставки партнёру файлом | Сервис ставок формирует файл с актуальными ставками и размещает его на SFTP. Система партнёрского кол-центра забирает файл по расписанию. |
| 7 | Оператор партнёрского кол-центра | Проконсультировать клиента по ставкам | Оператор партнёра видит актуальные ставки из последнего успешно загруженного файла. |
| 8 | Команда цифровой трансформации, IT | Контролировать актуальность передачи | В мониторинге видны время последней публикации ставок, результат загрузки в систему кол-центра и результат выгрузки файла на SFTP. |

## Нефункциональные требования

| № | Требование |
| :-: | :- |
| 1 | Ставки для операторов должны обновляться в день изменения ставок, целевой лаг публикации — не более 15 минут после утверждения в АБС. |
| 2 | Система кол-центра не должна обращаться напрямую к БД АБС. |
| 3 | Партнёрский кол-центр получает ставки только файлом через SFTP, без API-вызовов в системы банка. |
| 4 | Файлы для партнёра должны передаваться по защищённому каналу SFTP с аутентификацией ключами и ограниченными правами. |
| 5 | В файле для партнёра не должно быть персональных данных клиентов. Передаются только публичные ставки, параметры продуктов и дата актуальности. |
| 6 | Решение должно выдерживать рост звонков после маркетинговой кампании и не увеличивать нагрузку на АБС. |
| 7 | При недоступности АБС операторы должны видеть последнюю успешно опубликованную версию ставок с отметкой времени. |
| 8 | Должна быть история версий ставок и аудит публикаций. |
| 9 | Должны быть мониторинг, алерты и повторная отправка при сбоях публикации ставок во внутренний кол-центр или на SFTP. |
| 10 | Формат файла для партнёра должен быть версионирован и документирован. |
| 11 | Решение должно использовать технологии, совместимые с текущим ландшафтом: АБС Oracle/PL-SQL, система кол-центра Java Spring Boot/PostgreSQL, новый контур MVP на Java или .NET. |

## Решение

Диаграммы C4 вынесены в отдельные файлы:

- `c4-context-rates-call-centers.drawio` — контекстная диаграмма передачи ставок в кол-центры.
- `c4-component-rates-call-centers.drawio` — компонентная диаграмма сервиса ставок и файловой передачи партнёру.

### Принятое архитектурное решение

Для MVP ставки ведутся в АБС в модуле управления ставками, который был предложен в архитектуре Task3 как замена Excel. После утверждения ставки публикуются в `Rates API / Rate Cache` нового депозитного контура.

Внутренний кол-центр получает ставки из `Rates API` по внутреннему защищённому API. В системе кол-центра добавляется экран или виджет консультации по депозитам, где оператор видит продукт, срок, базовую ставку, условия и дату актуальности.

Партнёрский кол-центр получает ставки через файловый обмен:

1. `Rates Export Job` по событию изменения ставок или по расписанию формирует файл `deposit_rates_YYYYMMDD_HHMM.csv`.
2. `File Validation and Signing` проверяет состав полей, версию формата и контрольную сумму.
3. `SFTP Publisher` выкладывает файл на SFTP-сервер в каталог партнёра.
4. Система партнёрского кол-центра забирает файл с SFTP и загружает его во внутренний справочник операторов.
5. `Monitoring and Audit` фиксирует версию ставок, время публикации, результат выгрузки и ошибки.

Сайт, интернет-банк, внутренний кол-центр и партнёрский кол-центр используют один источник опубликованных ставок. Это снижает риск расхождения информации в каналах.

### Формат файла для партнёра

Минимальный состав файла:

| Поле | Описание |
| :- | :- |
| `format_version` | Версия формата файла. |
| `rate_version` | Версия публикации ставок. |
| `product_code` | Код депозитного продукта. |
| `product_name` | Название продукта. |
| `currency` | Валюта. |
| `term_from_days` / `term_to_days` | Диапазон срока. |
| `amount_from` / `amount_to` | Диапазон суммы. |
| `base_rate` | Базовая ставка. |
| `conditions_text` | Краткие условия для консультации. |
| `effective_from` | Дата и время вступления ставки в силу. |
| `published_at` | Дата и время публикации файла. |

Персональные ставки клиентов в файл партнёру не передаются.

### Команды, участвующие в разработке

| Команда | Зона ответственности |
| :- | :- |
| Команда АБС | Модуль ставок, ролевой доступ, публикация ставок в депозитный контур. |
| Команда депозитного контура MVP | `Rates API`, кэш ставок, экспорт файлов, мониторинг публикаций. |
| Команда системы кол-центра / подрядчик | Экран ставок для оператора, интеграция с `Rates API`, кэширование последней версии. |
| IT-инфраструктура банка | SFTP-сервер, ключи доступа, сетевые правила, мониторинг, резервирование. |
| Партнёрский кол-центр | Загрузка файла с SFTP, импорт ставок в рабочее место оператора, регламент обработки ошибок. |
| Команда цифровой трансформации | Согласование полей файла, SLA актуальности ставок, приоритеты RoadMap. |

## Альтернативы

| Альтернатива | Причина отказа |
| :- | :- |
| Давать системе кол-центра прямой доступ к АБС | Увеличивает нагрузку на перегруженную БД АБС и нарушает принцип изоляции онлайн-каналов от АБС. |
| Передавать ставки партнёру по email Excel-файлом | Быстро, но нет надёжного контроля доставки, версии, аудита и защищённого автоматического импорта. Это повторяет проблему текущего процесса. |
| Сделать API для партнёрского кол-центра | Партнёр не готов выполнять API-вызовы. Для MVP это увеличит сроки и не соответствует ограничению задания. |
| Вести отдельный справочник ставок в системе кол-центра | Появится второй источник правды, высокий риск расхождения ставок между сайтом, интернет-банком, кол-центром и АБС. |
| Передавать партнёру персональные ставки клиентов | Нельзя для MVP: повышает риски безопасности и требует передачи персональных данных во внешнюю систему. |

## Недостатки, ограничения, риски

- У партнёра ставки будут обновляться пакетно, а не в реальном времени. Нужно явно показывать дату актуальности.
- Если SFTP недоступен, партнёр будет работать по последней успешной версии файла.
- Для специальных персональных ставок оператор партнёра сможет дать только общую консультацию и направить клиента в банк или внутренний кол-центр.
- Потребуется согласовать регламент изменения формата файла, иначе обновления могут ломать импорт на стороне партнёра.
- Нужна эксплуатационная дисциплина: мониторинг, алерты, ротация ключей SFTP, контроль устаревших файлов.
- Если ставки продолжат жить в Excel, решение станет ненадёжным. Поэтому перенос ставок в АБС или управляемый модуль ставок является обязательной предпосылкой.
